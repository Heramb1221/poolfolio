# Poolfolio — Production Deployment Guide

This guide describes how to deploy the Poolfolio backend, PostgreSQL database, and Sentry monitoring to **Render**, and connect the React Native / Expo mobile application.

---

## 1. Quick Deploy via Render Blueprint (Recommended)

Poolfolio includes a declarative [render.yaml](../render.yaml) file at the repository root configuring both the PostgreSQL managed database and the Express backend web service.

### Step 1: Connect Repository to Render
1. Navigate to the [Render Dashboard](https://dashboard.render.com).
2. Click **New +** → **Blueprint**.
3. Select your GitHub repository (`poolfolio`).
4. Render will parse `render.yaml` and provision:
   - **`poolfolio-db`**: PostgreSQL 16 database (Oregon region).
   - **`poolfolio-api`**: Web service running Node.js 18+.

### Step 2: Configure Production Environment Variables
Set the following environment variables in the Render dashboard under `poolfolio-api`:

| Variable | Description | Example / Default |
|---|---|---|
| `NODE_ENV` | Production execution mode | `production` |
| `PORT` | Web server listening port | `10000` |
| `DATABASE_URL` | Auto-populated by Render from `poolfolio-db` | `postgresql://poolfolio:...@...render.com/poolfolio` |
| `JWT_SECRET` | Auto-generated secure random string (≥ 32 chars) | Render generates automatically |
| `JWT_EXPIRES_IN` | Token expiration | `7d` |
| `CLIENT_ORIGIN` | Allowed CORS origins (comma-separated or `*`) | `*` or `https://my-app.com,exp://` |
| `SENTRY_DSN` | Sentry project DSN for error/performance monitoring | `https://...@sentry.io/...` |
| `SENTRY_TRACES_SAMPLE_RATE` | Sentry performance transaction sample rate | `0.2` |
| `GEMMA_API_URL` | Endpoint for Ollama / vLLM Gemma model (optional) | `http://...` |
| `TABPFN_API_URL` | Endpoint for TabPFN tabular prediction (optional) | `http://...` |

### Step 3: Deployment Execution
Render executes:
1. **Build Command**:
   ```bash
   npm install --include=dev && npx prisma generate && npm run build
   ```
2. **Start Command (with automated migrations)**:
   ```bash
   npx prisma migrate deploy && npm start
   ```

## 2. Production PostgreSQL Database

### Connection Pooling & SSL
Render PostgreSQL requires SSL. The Prisma connection string generated by Render automatically includes `?sslmode=require`.

### Manual Migration Check
If applying migrations manually from a local shell:
```bash
cd server
export DATABASE_URL="postgresql://user:password@hostname:5432/poolfolio?sslmode=require"
npx prisma migrate deploy
```

## 3. Production Health Check & Monitoring

### Health Endpoint
Render monitors the application health via:
```http
GET /api/health
```

**Healthy Response (`200 OK`):**
```json
{
  "status": "ok",
  "message": "Poolfolio API is operational",
  "timestamp": "2026-10-03T15:00:00.000Z",
  "uptimeSeconds": 1420,
  "environment": "production",
  "version": "1.0.0",
  "services": {
    "database": "connected",
    "accountingEngine": "authoritative",
    "aiPipeline": "ready"
  }
}
```

If the database becomes unreachable, `/api/health` returns `503 Service Unavailable` with `status: "degraded"`.

## 4. Sentry Error & Latency Monitoring

Poolfolio integrates `@sentry/node` for production exception tracking and performance tracing.

1. Create a project at [sentry.io](https://sentry.io) (Project type: **Node.js / Express**).
2. Copy the **DSN** from Sentry Settings → Client Keys.
3. Paste the DSN into Render environment variable `SENTRY_DSN`.
4. Sentry will automatically:
   - Capture unhandled 500 exceptions in `errorHandler`.
   - Record distributed latency traces.
   - Tag issues with `environment: production`.

## 5. Connecting the Mobile App (Expo)

To point the React Native mobile app to the deployed Render API:

1. In `mobile/`:
   Create or update `.env`:
   ```bash
   EXPO_PUBLIC_API_URL="https://poolfolio-api.onrender.com/api"
   ```
2. Run the Expo development client or build:
   ```bash
   cd mobile
   npx expo start
   ```
3. To create an Android APK or iOS production build via EAS:
   ```bash
   eas build --platform all --profile production
   ```
